# ADR-0001：采用多引擎编排而非重写统一扫描引擎

- 状态：Accepted
- 日期：2026-08-12

## 背景

Java/Maven 审计同时涉及源码规则、字节码缺陷、跨过程污点、依赖漏洞、密钥、SBOM 和配置安全。单一开源引擎无法以同等质量覆盖这些领域。

## 决策

平台保留各成熟扫描器作为独立执行单元，自研部分集中在：

- 任务编排；
- 隔离运行；
- 结果适配；
- Finding 去重和策略；
- 统一报告。

对外呈现为一次扫描和一份报告，对内保留每个引擎的版本、状态、覆盖信息和原始证据。

## 影响

### 优点

- 复用成熟工具能力；
- 扫描器可以独立升级和失败隔离；
- 便于增加或替换引擎；
- 原始报告可审计、可追溯。

### 代价

- 需要维护多个输出适配器；
- 严重性、位置和规则语义不完全一致；
- 构建环境与扫描器版本矩阵更复杂；
- 跨引擎去重需要稳定指纹和证据模型。

## 未采用方案

- **只使用一个综合平台**：部署简单，但覆盖面、许可证和扩展边界受单一产品限制。
- **自行重写全部分析器**：长期成本极高，且难以达到成熟项目的准确度。
- **让 AI 直接阅读整个项目审计**：缺乏确定性覆盖证明，不适合作为 V1 核心。
