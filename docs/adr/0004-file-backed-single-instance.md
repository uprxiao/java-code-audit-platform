# ADR-0004：V1使用文件状态和单实例锁

- 状态：Accepted
- 日期：2026-08-12

## 背景

V1不需要用户体系、复杂历史查询或多实例协调。引入数据库会增加部署、备份和恢复成本。任务天然具有自包含目录：源码、日志、原始报告和最终报告。

## 决策

- 内存索引用于运行期查询和调度；
- `data/jobs/{scanId}/job.json`等文件是持久化事实；
- 所有关键状态原子写入并带revision；
- `data/instance.lock`确保一个data目录只有一个实例；
- 启动恢复QUEUED和终态任务，运行中任务标记INTERRUPTED；
- SVN密码不持久化；
- 文件保留和清理按冻结策略执行；
- V1不支持共享NFS上的多实例。

## 影响

- 无外部数据库即可启动；
- 状态可人工检查并与报告一起归档；
- 查询和分页规模受单机内存/文件数量限制；
- 必须严格处理原子写入、损坏状态、文件锁和安全删除；
- 未来多实例时需要迁移到数据库/队列或单独控制面。

## 未采用方案

- 嵌入式H2/SQLite：仍增加Schema迁移和备份复杂度，当前收益有限；
- PostgreSQL：适合多用户与查询，但不符合V1轻量工具目标；
- 只有内存：重启会丢失任务和报告索引。
