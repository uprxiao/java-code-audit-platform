# V1 安全边界

## 1. 最重要的事实

V1 **没有容器或恶意代码沙箱**。它会在宿主机以服务账户权限运行 Maven 和扫描器。`mvn -DskipTests package` 仍会执行构建插件、注解处理器和生命周期代码，因此仅限扫描维护者信任且有权分析的源码。

```text
可信来源代码 + 可信网络：V1适用
任意公网匿名上传 + 恶意项目：V1不适用
```

如果未来要接收不可信用户代码，必须重新设计容器/沙箱、网络、凭据、内核和租户隔离，不能通过增加几个路径校验宣称安全。

## 2. API 暴露

V1 不实现认证，允许监听外部地址。最低部署要求：

- 仅在个人机器、VPN或可信内网开放；
- 使用主机防火墙限制来源；
- 需要公网时由反向代理提供 TLS 和认证，但这不属于 V1 自身；
- 不在服务账户环境中放置生产云密钥、SSH私钥或无关 Token；
- 不使用管理员/root账户运行；
- 报告下载和删除接口同样只在可信边界内开放。

## 3. ZIP 防护

- 上传流1 GB上限；
- 展开后10 GB、单文件1 GB、20万文件、最大压缩比100:1；
- 拒绝绝对路径、盘符、UNC、`..`、NUL和规范化逃逸；
- 拒绝危险 symlink/hardlink/device entry；
- 边读取边计数，超限立即停止；
- 文件权限归一化，不保留 setuid/setgid；
- 目标路径必须 `normalize().startsWith(workspaceRoot)`；
- 不执行 ZIP 内启动脚本，Maven阶段除外且只针对可信项目。

## 4. SVN 防护

- 支持 HTTP/HTTPS/svn，禁止 file 和 svn+ssh；
- URL长度和格式限制；
- 重定向按客户端安全策略处理；
- 允许访问内部 SVN，因此默认不能用简单“禁止私网”规则；部署者可配置 host allowlist；
- 用户名/密码只在检出内存中；
- 不写 job、日志、报告和进程列表；
- 使用系统证书信任链；默认不跳过自签名证书验证；
- 需要内网 CA 时配置 JVM truststore，而不是 `trust-all`；
- 凭据任务在检出前重启后要求重新提交。

## 5. 进程执行

- 使用参数数组和绝对工具路径；
- 禁止 Shell；
- 工作目录限制在任务目录；
- 环境变量允许清单；
- 清除不需要的 `GITHUB_TOKEN`、云凭据、SSH agent 等继承环境；
- Maven属性名称和值校验，禁止 goal、settings路径、JVM Agent和重定向；
- stdout/stderr并发读取，避免死锁；
- 超时/取消时终止进程及全部 descendants；
- 每个引擎输出目录独占；
- 扫描器可执行文件启动前校验版本和 SHA256。

## 6. 文件系统和账户

- 单独的低权限 OS 账户；
- tools目录只读，data目录可写；
- 不让服务账户访问其他项目源码和生产配置；
- Linux推荐 systemd `ProtectSystem`、`PrivateTmp`、`NoNewPrivileges`、`LimitNOFILE`、`TasksMax`、`MemoryMax`；
- 不挂载 Docker socket；
- 不复用用户个人 HOME 作为任务工作区；
- 所有递归清理目标必须经过固定根校验。

Mac 本机运行无法提供完整账户隔离，必须确认扫描目标可信。

## 7. 网络

联网是V1前提：SVN、Maven和漏洞库需要网络。风险控制：

- 代理和 Maven settings 由部署配置提供；
- Maven插件仍可访问网络，这是可信代码边界的一部分；
- 漏洞数据库只从清单中的官方源更新；
- 工具下载在维护/组装阶段完成并校验哈希；
- 正常启动不自动升级工具；
- 记录数据库来源和时间，不记录代理密码；
- 后续如需出站 allowlist，需要结合实际 Maven私服和SVN环境设计。

## 8. 凭据与密钥脱敏

统一 Redaction Service 处理：

- SVN password；
- URL user-info；
- Maven敏感属性；
- proxy/server credential；
- Gitleaks/Trivy检出的密钥；
- CodeQL/扫描器日志中的敏感环境变量。

脱敏在日志写入前、Finding构造前、原始报告归档前分别执行；不能只依赖前端隐藏。测试使用 canary secret 并扫描整个下载包，确保明文不存在。

## 9. 第三方供应链

- 工具版本锁定；
- 下载来源为官方发布；
- 保存 SHA256，支持时校验签名/Sigstore；
- 许可复核后才允许再分发并进入 Git LFS；
- 升级通过跨平台真实扫描和 Parser回归；
- 动态数据原子更新并保留旧完整版本；
- 报告记录实际工具、规则和数据库版本。

CodeQL CLI 不提交、不公开再分发，并按[当前条款](https://github.com/github/codeql-cli-binaries/blob/main/LICENSE.md)和目标项目资格使用。

## 10. 报告安全

- 不包含完整源码；
- 普通问题只含有限上下文；
- 密钥始终遮蔽；
- 原始工具报告也脱敏；
- HTML不加载外部脚本/CDN；
- 源码文本做 HTML escaping，防止报告打开时执行脚本；
- ZIP中的报告文件名由平台生成；
- 下载 Content-Disposition 防 CRLF/文件名注入；
- 归档创建时防止路径穿越。

## 11. 不宣称的保证

- 不能阻止可信项目中的有害 Maven插件影响宿主账户；
- 不能保证静态扫描无误报/漏报；
- 不能证明依赖漏洞可达；
- 不能扫描 SVN历史密钥；
- 不能保护无认证公网部署；
- 不能替代人工业务逻辑、安全架构和运行时测试。

## 12. 安全升级触发条件

出现任一条件必须停止沿用 V1 威胁模型：

- 接收非维护者上传；
- 多用户/多租户；
- 扫描闭源或许可未知代码并启用受限工具；
- 服务账户拥有生产凭据；
- 需要公网匿名访问；
- 要求攻击者模型下的隔离保证。

此时应新增 ADR，优先拆分执行平面并引入经过验证的沙箱/容器和网络策略。
